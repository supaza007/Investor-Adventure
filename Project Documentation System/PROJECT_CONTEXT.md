## 1. Project Summary

- ชื่อโปรเจกต์: เกมการลงทุน บูรณาการ
- ประเภทผลิตภัณฑ์: เกม/สื่อการเรียนรู้ด้านการลงทุน
- เป้าหมายหลัก: สอนการจัดพอร์ตและความสัมพันธ์ระหว่างความเสี่ยง ผลตอบแทน การกระจายความเสี่ยง และพฤติกรรม ผ่านเกมจำลองเส้นทางชีวิตนักลงทุน
- ปัญหาที่ต้องการแก้: ทำให้แนวคิดการลงทุนที่เป็นนามธรรมเห็นผลจากการตัดสินใจได้ภายในเกมสั้น
- ผลลัพธ์ที่ต้องการให้ผู้เล่นได้รับ: อธิบายได้ว่าคุณภาพการเตรียมพอร์ตและความผันผวน/ดวงส่งผลต่อผลลัพธ์แยกกันอย่างไร

## 11. Documentation Map

1. `PROJECT_CONTEXT.md` — ทำไมจึงสร้างโปรเจกต์และขอบเขตคืออะไร
2. `GAME_DESIGN.md` — เกมเล่นอย่างไรและประสบการณ์ที่ต้องการคืออะไร
3. `SYSTEM_SPEC.md` — ระบบต้องทำอะไรและประกอบด้วยอะไร
4. `UI_SPEC.md` — หน้าจอ สถานะ และพฤติกรรม UI
5. `PROJECT_STATUS.md` — ตอนนี้อยู่ที่ไหน กำลังทำอะไร และทำอะไรต่อ
6. `DECISIONS.md` — ตัดสินใจอะไรไปแล้ว เพราะเหตุใด

## 12. Rules for AI Sessions

- อ่านเอกสารทั้ง 6 ไฟล์ก่อนแก้โค้ดหรือสเปกที่มีผลต่อระบบ
- ตรวจโค้ดและผลทดสอบจริงก่อนสรุปว่า feature ทำงานแล้ว
- ไม่เปลี่ยนข้อมูล `TBD` เป็นข้อเท็จจริงโดยไม่มีหลักฐานหรือคำยืนยัน
- หากเอกสารขัดกัน ให้ยึดลำดับ: Decision ที่ Active → สเปกเฉพาะด้าน → Project Context → Project Status
- เมื่อเปลี่ยนพฤติกรรมระบบ ต้องอัปเดตสเปกที่เกี่ยวข้องใน Session เดียวกัน
- เมื่อมีการเลือกแนวทางสำคัญ ต้องเพิ่มรายการใน `DECISIONS.md`
- ก่อนจบ Session ต้องอัปเดต `PROJECT_STATUS.md` พร้อมหลักฐานและ Next Actions
